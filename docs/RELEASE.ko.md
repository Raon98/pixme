# 출시 체크리스트

`RELEASE.md`의 한국어판입니다. 아래 항목은 전부 App Store / Play 최초 제출
전에 실제로 필요한 것들입니다.

**🚩 필수** 표시는 미룰 수 없는 항목입니다 — 법적 요건이거나, 스토어 심사
반려 사유이거나, 돈이 새는 구멍입니다.

---

## 0. 캐릭터 레퍼런스 (이번 작업에서 추가됨)

- [ ] **🚩 필수** 공식 마스터 캐릭터 이미지를
      `apps/server/src/main/resources/pixme/master-character-v1.png` 에 추가
      > 없으면 서버가 경고를 남기고 프롬프트만으로 생성합니다 — 캐릭터 패밀리가
      > 흔들립니다.
- [ ] **🚩 필수** 운영 환경에서 `PIXME_MASTER_REFERENCE_REQUIRED=true`
      > 레퍼런스 없이 배포되는 사고를 막습니다.
- [ ] 서버 기동 로그의 `measured spec` 값 확인 (머리 비율, 캔버스 점유율, 바닥선)
      > 모든 캐릭터가 이 수치로 정규화됩니다.
- [ ] 실제 AI 키를 넣고 사진 10장 정도로 생성해 **같은 세계관으로 보이는지** 눈으로 확인
      > 프롬프트와 정규화가 보장하는 것은 비율·정렬이고, 그림체 일관성은
      > 레퍼런스 품질에 달려 있습니다.

## 1. 계정 및 자격 증명

- [ ] **🚩 필수** Apple Developer Program 가입, Bundle ID `com.pixme.app`
- [ ] **🚩 필수** Sign in with Apple capability 활성화 + `PIXME_APPLE_CLIENT_IDS`에
      실제로 배포하는 Bundle ID만 정확히 설정
      > `aud` 검증이 없으면 **다른 앱에서 발급된 토큰으로도 로그인**이 됩니다.
- [ ] **🚩 필수** Kakao Developers 앱 생성 — REST 키는 클라이언트,
      **Client Secret은 서버에만**
- [ ] **🚩 필수** `PIXME_JWT_SECRET` 환경별로 32바이트 이상 랜덤값
      > 짧으면 서버가 아예 부팅을 거부합니다.
- [ ] **🚩 필수** `PIXME_APPLE_ROOT_CERTS`에 Apple 루트 CA 경로 설정
      > 없으면 영수증 인증서 체인 검증이 생략되고 서버가 경고를 남깁니다.
      > 개발에선 괜찮지만 **운영에선 절대 안 됩니다.**
- [ ] **🚩 필수** Google Play 서비스 계정 JSON (영수증 검증용)
- [ ] AI Provider API 키 + **지출 한도(spend cap) 설정**
- [ ] Expo 푸시용 Access Token

## 2. 스토어 설정

- [ ] 인앱결제 상품 생성 및 **승인 완료**, ID가 `products` 테이블과 일치
      (`app.pixme.credit.1|3|10`, `app.pixme.style.*`, `app.pixme.decor.*`,
      `app.pixme.plus.monthly`)
- [ ] PIXME+ 구독 그룹 및 지역별 가격 설정
- [ ] **🚩 필수** 앱 안에 구독 정보 명시 — 가격, 기간, 자동 갱신, 해지 방법
      > Apple은 이 표기가 없는 구독을 반려합니다. (현재 `plus.tsx`에 포함)
- [ ] **🚩 필수** "구매 복원"이 로그인 없이도 도달 가능
      > 스토어 화면과 설정 두 곳에 있습니다.
- [ ] 샌드박스 전체 검증: 구매 → 지급 → 복원 → **Play 보류(pending) 결제** → 만료
      > 보류 상태를 지급으로 처리하면 무료로 생성권이 나갑니다.

## 3. 법무 및 개인정보

- [ ] **🚩 필수** 이용약관·개인정보처리방침을 `app.config.ts`의 `extra` URL에 게시,
      **로그인 전에** 접근 가능 (로그인 화면에 링크되어 있음)
- [ ] **🚩 필수** 개인정보처리방침에 다음을 명시: 사진을 캐릭터 생성 목적으로
      업로드함, AI 업체로 전송함, N일간 보관함, 개별 삭제 및 보관 끄기 가능함
- [ ] **🚩 필수** App Privacy / Data Safety 신고 내용이 실제와 일치
      (사진, 이메일, 사용자 콘텐츠, 식별자) — `PRIVACY.md`와 교차 확인
      > 부정확한 신고는 반려 사유이자 컴플라이언스 문제입니다.
- [ ] **🚩 필수** 계정 삭제가 **앱 안에서** 가능 (MY → 설정 → 계정 삭제)
      > 회원가입이 있는 앱은 App Store 가이드라인 5.1.1(v) 필수 요건입니다.
- [ ] **🚩 필수** AI 업체의 데이터 보관 약관 검토 후 방침에 반영
      > 우리가 사용자에게 약속할 수 있는 내용을 바꾸는 **유일한 외부 의존성**입니다.
- [ ] 연령 등급: iOS 17+ (UGC + 비검열 1:1 대화 포함)
- [ ] 만 14세 이상 제한 적용 확인 (`UserService.requireMinimumAge`에 구현됨) 및
      약관에 명시
- [ ] 한국: 위치정보사업자 신고 **불필요** (위치정보 미수집). 결제가 전부 플랫폼
      스토어를 거치므로 통신과금 해당 여부는 법률 검토 권장

## 4. 안전 — UGC 가이드라인 1.2

Apple은 사용자 생성 콘텐츠가 있는 앱에 아래 4가지를 **모두** 요구합니다.
전부 구현되어 있으니, 빌드된 바이너리에서 각각 도달 가능한지 확인하세요.

- [ ] **🚩 필수** 부적절한 콘텐츠 필터링 수단
      → 생성 전 이미지 안전검사 + 닉네임·한줄소개·한마디·태그 텍스트 필터
- [ ] **🚩 필수** 신고 수단
      → 프로필·게시물·채팅에서 신고 시트, "함께 차단" 기본 ON
- [ ] **🚩 필수** 차단 수단
      → 즉시·전면·양방향 (피드, 광장, 프로필, 추천, 대화 모두)
- [ ] **🚩 필수** 고객 지원 연락처 공개
      → `PIXME_SUPPORT_EMAIL`, 설정에 링크
- [ ] 사람이 24시간 안에 신고를 처리할 수 있는 체계
      > 24시간 내 서로 다른 3명이 신고하면 자동 보류되지만, 그건 임시 조치일 뿐
      > 검토를 대신하지 못합니다.
- [ ] 운영 매뉴얼 작성: 누가 검토하는지, 조치 종류, 제한된 사용자의 이의 절차

## 6. 인프라

- [ ] Postgres 자동 백업 + PITR
- [ ] Redis (레이트 리미터는 장애 시 통과시키므로, 가용성 이슈이지 정합성 이슈는 아님)
- [ ] **🚩 필수** 원본 버킷이 완전 비공개 — public 정책 없음, CDN 연결 없음
      > 오브젝트 키로 직접 요청해서 실제로 막히는지 확인하세요.
- [ ] 캐릭터 버킷은 CDN + 긴 캐시 TTL (생성된 캐릭터는 불변)
- [ ] 원본 prefix에 lifecycle 규칙 — 보관 기간 잡(job)의 2차 방어선
- [ ] 운영 환경에서 예약 작업이 실제로 도는지 확인
      > 특히 `reapStuckGenerations` — 배포/크래시 중에도 생성권 환불을 보장하는
      > 유일한 장치입니다.
- [ ] 알림 설정: 생성 실패율, Provider 지연/지출, 멈춘 생성, 5xx 비율, 푸시 실패율
- [ ] 점검 모드·강제 업데이트 레버 동작 확인
      (`PIXME_MAINTENANCE`, `PIXME_MIN_APP_VERSION`)
      > 잘못된 릴리스를 멈출 수 있는 **유일한** 수단입니다.

## 7. 출시 첫날 콘텐츠

광장이 비어 있는 소셜 앱은 죽은 앱으로 보입니다. 마케팅 전에:

- [ ] 광장 시딩 — 첫 사용자가 빈 광장이 아니라 다른 사람들의 오늘을 보게
- [ ] 사용자가 적을 때도 신규 유저 쿼터가 실제로 신규를 노출하는지 확인
- [ ] 출시 지역 결정 — 현재 광장은 전 세계 단일 공간입니다. 초기에는 괜찮지만
      규모가 커지면 분리가 필요합니다

## 8. 출시 전 판단이 필요한 알려진 제약

| 제약 | 영향 |
| --- | --- |
| 실시간 채팅이 단일 노드 | 다른 인스턴스에 붙은 사용자는 즉시 프레임을 놓치고 푸시+다음 조회로 받습니다. 출시 시점엔 괜찮고, 확장 전에 `ChatSessionRegistry` 뒤에 Redis pub/sub만 추가하면 됩니다. |
| 광장은 단일 공간, 최신 N명 | 하루 게시물이 캔버스를 넘으면 먼저 올린 사람이 캔버스에서 빠집니다(피드에는 남음). 규모가 커지면 분리/페이지네이션 필요. |
| 운영은 신고 기반 | 게시된 캐릭터를 사전 검토하지 않습니다. 결과물이 양식화된 픽셀 아트라 수용 가능하지만, 큐를 볼 사람이 필요합니다. |
| 다크 모드는 구조만 완성 | 모든 컴포넌트가 시맨틱 컬러를 읽고 설정에서 선택 가능하지만, 디자인을 마무리한 쪽은 라이트 모드입니다. |
